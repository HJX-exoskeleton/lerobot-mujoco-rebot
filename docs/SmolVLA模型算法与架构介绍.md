# SmolVLA 模型算法与架构介绍

## 1. VLA 模型概述

视觉—语言—动作模型（Vision-Language-Action Model，VLA）将视觉感知、自然语言理解与机器人控制统一到一个端到端策略中。其基本映射可以表示为：

```text
π_θ:
(o_t^{image},o_t^{state},l)
→
a_{t:t+H-1},
```

其中：

- `o_t^{image}` 是时刻 `t` 的视觉观测；
- `o_t^{state}` 是机器人自身状态；
- `l` 是自然语言任务指令；
- `a_{t:t+H-1}` 是未来长度为 `H` 的动作序列；
- `π_θ` 是参数为 `θ` 的机器人策略。

在当前 reBot 项目中，模型输入为：

```text
o_t=
(
I_t^{agent},
I_t^{wrist},
q_t,
l
),
```

其中 `I_t^{agent}` 为第三视角图像，`I_t^{wrist}` 为腕部相机图像，`q_t∈ℝ^{6}` 为六个机械臂关节角，`l` 为类似 “Place the blue mug on the plate.” 的语言指令。

模型输出为：

```text
A_t=[a_t,a_{t+1},…,a_{t+H-1}],
    
a_t∈ℝ^{7},
```

动作的前 6 维为机械臂关节目标，第 7 维为夹爪动作。

与只针对单一任务训练的行为克隆策略相比，VLA 可以利用语言区分同一场景中的不同任务，例如选择红色杯子或蓝色杯子。

## 2. SmolVLA 的设计目标

SmolVLA 是一种面向低成本机器人平台的轻量级 VLA。它使用紧凑的视觉语言模型作为语义与视觉骨干，并增加专门用于连续机器人控制的动作专家。

其主要目标包括：

- 使用视觉语言模型理解场景和任务指令；
- 使用机器人状态提供精确的运动学信息；
- 使用动作专家生成连续动作轨迹；
- 使用条件流匹配建模动作分布；
- 降低模型训练和部署所需显存；
- 支持消费级 GPU 上的微调和推理。

当前项目可以在 RTX 4060 Laptop 8GB 显存上运行 SmolVLA，说明其轻量化设计适合低成本机器人研究、仿真验证及中小规模数据集实验。

## 3. SmolVLA 总体架构

SmolVLA 可以划分为四个主要部分：

```text
SmolVLA
=
视觉编码器
+
语言模型
+
状态投影层
+
动作专家.
```

整体数据流可以表示为：

```text
(I_t^1,I_t^2,l,q_t)
--VLM→
C_t
--Action Expert→
v_θ(x_τ,τ| C_t)
--ODE 积分→
A_t.
```

其中：

- `C_t` 是图像、语言和机器人状态构成的条件表示；
- `x_τ` 是流匹配过程中的中间动作变量；
- `τ∈[0,1]` 是流匹配时间；
- `v_θ` 是动作专家预测的速度场；
- `A_t` 是最终动作块。

### 3.1 视觉编码

相机图像首先被缩放并填充到统一尺寸，然后将像素范围从 `[0,1]` 映射到 `[-1,1]`。视觉编码器将图像转换为视觉 token：

```text
Z_t^{(i)}=f_{vision}(I_t^{(i)}).
```

当前项目使用第三视角和腕部视角两个相机，因此：

```text
Z_t^{vision}
=
[
Z_t^{agent};
Z_t^{wrist}
].
```

第三视角提供杯子、盘子和机械臂之间的全局空间关系，腕部相机则在靠近和抓取阶段提供局部视觉信息。

### 3.2 语言编码

自然语言指令经过 tokenizer 转换为 token 序列：

```text
l→(w_1,w_2,…,w_N),
```

再经过嵌入层得到：

```text
Z^{lang}
=
[E(w_1),E(w_2),…,E(w_N)].
```

语言条件使模型可以在相同视觉场景中执行不同任务。例如，“Place the red mug on the plate.” 与 “Place the blue mug on the plate.” 会引导模型生成不同的接近和抓取轨迹。

### 3.3 机器人状态编码

当前 reBot 状态为六维关节角：

```text
q_t=[q_t^1,q_t^2,…,q_t^6]∈ℝ^{6}.
```

SmolVLA 内部支持最大 32 维状态，因此首先将状态零填充为：

```text
bar q_t=[q_t^1,…,q_t^6,0,…,0]∈ℝ^{32}.
```

状态随后通过线性投影进入 VLM 隐藏空间：

```text
z_t^{state}=W_sbar q_t+b_s.
```

关节状态可以提供仅靠图像难以精确估计的机械臂构型信息。

### 3.4 多模态条件前缀

视觉、语言和状态 token 共同组成条件前缀：

```text
C_t=
[
Z_t^{vision};
Z^{lang};
z_t^{state}
].
```

该条件表示负责建立语言目标、图像区域、当前机器人构型和未来动作之间的关系。

## 4. 动作专家网络

SmolVLA 没有直接使用完整视觉语言模型回归机器人动作，而是增加了一个动作专家（Action Expert）。

动作专家接收：

```text
(x_τ,τ,C_t)
```

并预测条件速度场：

```text
v_θ(x_τ,τ| C_t).
```

视觉语言骨干主要负责理解“看到了什么”和“任务要求做什么”，动作专家负责生成“机械臂接下来应该怎样运动”。

当前项目配置中，动作专家隐藏宽度约为 VLM 隐藏宽度的：

```text
d_{expert}=0.75d_{VLM}.
```

训练时冻结视觉编码器和大部分 VLM 参数，主要更新动作专家、状态投影层和动作投影层。这可以减少需要保存的梯度和优化器状态，从而显著降低训练显存。

## 5. 动作分块

SmolVLA 一次生成多个未来动作：

```text
A_t=[a_t,a_{t+1},…,a_{t+H-1}].
```

当前配置为：

```text
H=5.
```

在 20Hz 控制频率下，一个动作块覆盖：

```text
(5)/(20)=0.25 s.
```

模型推理一次生成 5 个动作并存入队列，控制循环逐个执行。队列耗尽后，模型再根据最新图像和机器人状态生成新的动作块。

动作分块可以提高轨迹连续性、减少 VLM 调用频率并降低逐帧预测抖动。但动作块过长也会降低闭环纠错频率，因此其长度是推理效率与实时反馈能力之间的折中。

## 6. 条件流匹配

### 6.1 生成式动作建模

同一个机器人观测可能对应多条合理轨迹。例如机械臂绕开障碍物时，可以从不同方向接近目标。

如果采用普通均方误差直接回归：

```text
hat A=f_θ(C),
```

```text
mathcal L_{BC}
=
|A-hat A|_2^2,
```

模型可能对多条合理轨迹取平均，产生实际并不安全的中间动作。

流匹配不直接预测动作均值，而是学习一个将简单噪声分布连续变换为真实动作分布的速度场。

### 6.2 数据与噪声之间的路径

设真实动作块为：

```text
x_0=A,     x_0∼ p_{data}.
```

采样标准高斯噪声：

```text
x_1=ε,    ε∼mathcal N(0,I).
```

SmolVLA 在真实动作与高斯噪声之间构造线性路径：

```text
x_τ=(1-τ)x_0+τ x_1,
    τ∈[0,1].
```

当 `τ=0` 时：

```text
x_τ=x_0=A,
```

即真实动作；当 `τ=1` 时：

```text
x_τ=x_1=ε,
```

即纯高斯噪声。

### 6.3 目标速度场

对线性路径求导：

```text
(dx_τ)/(dτ)=x_1-x_0.
```

因此真实目标速度为：

```text
u_τ=ε-A.
```

动作专家预测：

```text
v_θ(x_τ,τ| C).
```

条件流匹配损失为：

```text
mathcal L_{FM}(θ)
=
mathbb E_{
A∼ p_{data},
ε∼mathcal N(0,I),
τ∼ p(τ)
}
[
|
v_θ(x_τ,τ| C)
-
(ε-A)
|_2^2
].
```

当前实现的时间变量首先按照下式采样：

```text
τ'∼Beta(1.5,1.0),
```

然后映射为：

```text
τ=0.001+0.999τ'.
```

这会调整不同噪声水平样本在训练中的比例。

## 7. 时间编码

动作专家需要同时知道带噪动作 `x_τ` 和当前噪声程度 `τ`。SmolVLA 使用正弦—余弦编码表示流匹配时间：

```text
e_τ^{(2k)}=sin(ω_kτ),
```

```text
e_τ^{(2k+1)}=cos(ω_kτ).
```

带噪动作经过输入投影：

```text
e_x=W_{in}x_τ+b_{in}.
```

随后与时间编码拼接，并通过 MLP 融合：

```text
e_{x,τ}=[e_x;e_τ],
```

```text
h_τ=
W_2SiLU(W_1e_{x,τ}+b_1)+b_2.
```

动作专家处理融合后的动作 token，最终通过输出投影得到速度：

```text
v_θ=W_{out}h_θ+b_{out}.
```

## 8. 推理阶段的反向流积分

训练阶段学习的是从真实动作指向噪声的速度方向：

```text
A→ε.
```

推理阶段从高斯噪声开始，沿相反时间方向积分回真实动作分布。

首先采样：

```text
x_1∼mathcal N(0,I).
```

然后求解条件常微分方程：

```text
(dx_τ)/(dτ)
=
v_θ(x_τ,τ| C),
```

并将时间从 `τ=1` 积分到 `τ=0`。

当前配置使用 10 个 Euler 积分步骤：

```text
Deltaτ=-(1)/(10)=-0.1.
```

每一步更新为：

```text
x_{τ+Deltaτ}
=
x_τ+Deltaτ
v_θ(x_τ,τ| C).
```

经过 10 次速度场预测后得到最终动作块：

```text
hat A=x_0.
```

## 9. KV Cache

在一次流匹配采样过程中，图像、语言和机器人状态保持不变，只有 `x_τ` 和 `τ` 随积分步骤变化。

SmolVLA 首先计算条件前缀：

```text
C=f_{VLM}(I,l,q),
```

并保存注意力中的 Key 和 Value。之后每个去噪步骤只重新处理动作 token：

```text
v_θ(x_τ,τ| C_{cache}).
```

因此，10 步流积分不需要重复运行 10 次完整视觉编码器。KV Cache 是提高 SmolVLA 推理效率的重要机制。

## 10. 状态与动作归一化

机械臂各个状态和动作维度的数值范围不同。SmolVLA 对状态和动作采用均值—标准差归一化：

```text
tilde q_j=frac{q_j-μ_{q_j}}{σ_{q_j}},
```

```text
tilde a_j=frac{a_j-μ_{a_j}}{σ_{a_j}}.
```

模型在归一化空间中学习。推理结束后，动作被反归一化：

```text
hat a_j=σ_{a_j}tilde a_j+μ_{a_j}.
```

当前 reBot 数据中的夹爪动作使用物理关节位置：

```text
a^{gripper}∈{0.001,0.05}.
```

模型输出反归一化后仍处于该物理位置空间，而环境控制接口要求 `0` 表示张开、`1` 表示闭合。因此推理阶段使用带迟滞区间的转换：

```text
g=
begin{cases}
1,&a^{gripper}leqτ_{close},
0,&a^{gripper}geqτ_{open},
g_{previous},&其他情况.
end{cases}
```

迟滞区间可以避免连续模型输出在阈值附近波动时导致夹爪高频开合。

## 12. 显存占用较低的原因

SmolVLA 能够在 8GB 显存的 RTX 4060 Laptop 上运行，主要有以下原因。

### 12.1 视觉语言骨干较小

当前使用约 500M 规模的 SmolVLM2 骨干，相比更大的 VLA 基础模型，其模型参数和中间激活占用更低。

### 12.2 冻结视觉语言模型

训练时冻结视觉编码器和大部分 VLM：

```text
∇_{θ_{VLM}}mathcal L=0.
```

主要优化：

```text
θ_{train}
=
{
θ_{expert},
θ_{state_proj},
θ_{action_proj}
}.
```

冻结参数不需要保存训练梯度和完整的 Adam 优化器状态，因此可以显著降低训练显存。

### 12.3 动作专家宽度较小

```text
d_{expert}=0.75d_{VLM}.
```

动作专家比完整 VLM 更窄，降低了连续动作建模所需的计算量。

### 12.4 KV Cache

推理时复用视觉、语言和状态前缀，避免每个 Euler 步骤重复执行完整多模态编码。

### 12.5 动作序列较短

当前动作块长度只有 5，动作 token 数量较少，动作专家的注意力和中间激活开销相对有限。

## 13. SmolVLA 与 ACT

ACT 通常通过 Transformer 一次性回归动作块：

```text
hat A=f_θ(o_t).
```

SmolVLA 从随机噪声开始，通过条件速度场逐步生成动作：

```text
ε
--velocity field→
hat A.
```

ACT 的结构更直接、推理速度更快，适合作为单任务模仿学习基线。SmolVLA 则具有以下特点：

- 原生支持视觉和语言联合条件；
- 可以通过语言在同一场景中区分多个任务；
- 使用生成式方法建模动作分布；
- 可以利用视觉语言预训练知识；
- 动作专家专门学习连续机器人控制。

其代价是生成一次动作需要进行多次速度场计算，因此推理计算量通常高于直接动作回归。

## 14. SmolVLA 与 Pi0

SmolVLA 和 Pi0 都采用视觉、语言、机器人状态和动作专家相结合的 VLA 范式，并使用流匹配生成连续动作：

```text
(I,l,q)
→
C
→
v_θ(x_τ,τ| C)
→
A.
```

二者主要区别在于基础模型规模、网络结构和硬件资源需求。Pi0 通常具有更大的视觉语言骨干，而 SmolVLA 更强调轻量化训练和低成本硬件部署。

对于当前 reBot 项目：

- ACT 可以作为可靠的单任务行为克隆基线；
- SmolVLA 适合研究轻量级语言条件控制；
- Pi0 可用于进一步研究更大规模 VLA 的迁移能力；
- SmolVLA 在模型能力、训练成本和消费级 GPU 可运行性之间具有较好的平衡。

## 15. 总结

SmolVLA 是一个以轻量视觉语言模型为感知和语义基础、以动作专家为连续控制模块、以条件流匹配为动作生成方法的端到端机器人策略。

其核心学习目标是条件速度场：

```text
v_θ(x_τ,τ| I,l,q).
```

该速度场描述如何在给定图像、语言指令和机器人状态的条件下，将高斯噪声逐步转换为合理的动作序列。

训练阶段学习：

```text
A→ε
```

之间的速度方向，推理阶段则通过反向 ODE 积分完成：

```text
ε→ A.
```

这种方法将视觉理解、语言条件、机器人状态感知和连续动作生成统一到同一框架中。对于计算资源有限的机器人平台，SmolVLA 提供了一条能够在消费级 GPU 上完成训练和部署的 VLA 研究路线。
